Metal volume image-compare failures (run: Aug 06 2026, full RenderingVolumeCxx-Metal suite)

Out-of-bounds samples on the entry side of the [0,1]^3 texture cube are now
clamped and composited (boundary slab) instead of skipped. The OpenGL backend
never drops these samples: its clamp-to-edge sampler clamps the coordinate back
into the cube and composites the boundary voxel. For axis-aligned volumes this
only affects grazing rays whose first step exits the cube (sample-positions
outside the cube imply the ray chord is shorter than one step), which is exactly
why the Metal contour was ~3px slimmer per side than the GL baseline. This
fixes TestGPURayCastMapperSampleDistance (0.1419 -> pass): previously the
corner-grazing rays composited nothing, so the RGB contour shrank; now the
clamped first sample matches the baseline. seenInBounds stays false while
entry-side samples are outside so rotated-volume corner regions still march
(and composite) through to the data cube, and axis-aligned grazing rays still
terminate via the block-bounds exit.

Gradient opacity no longer depends on shading being enabled: the Metal backend
was gating UseGradientOpacity on property->GetShade(), but the OpenGL backend
applies gradient opacity whenever the property declares it. This fixes
TestGPURayCastTwoComponentsGradient (0.4505 -> pass): previously the whole
right-half box rendered as a plain purple slab (gradient opacity skipped), the
baseline shows only the x=17 boundary plane sliver with gradient darkening at
the top/bottom edges.

The shader now applies gradient opacity to the per-sample alpha outside the
shading block for the dependent-composite path, and the gradient-opacity LUT is
built over the LAST component's scalar range in dependent multi-component mode
(OpenGL vtkVolumeInputHelper passes numComp - 1 for the LA/RGBA mode; the
shader still normalizes the gradient magnitude against the component it is
computed on). This fixes TestGPURayCastTwoComponentsDependentGradient
(0.2281 -> pass): previously the quadrant interiors rendered solid (gradient
opacity skipped when shading is off) and the boundary cross stayed dimmed
(the baseline brightens the boundary planes via the opacity component's range).

4-component dependent (RGBA) data is now treated as raw RGBA: color comes from
scalar.xyz directly and opacity from scalar.w mapped through the opacity LUT
built over the LAST component's range (OpenGL computeColor/computeOpacity RGBA
parity — computeColor returns vec4(scalar.xyz, opacity), computeOpacity reads
scalar.w). The gradient-opacity LUT and the shader gradient normalization range
also follow the last component in this mode. This fixes
TestGPURayCastFourComponentsDependentGradient (0.1773 -> pass): previously the
vase rendered ~4x dimmer because the color came from the default color LUT
(black@0 / white@1024) instead of the raw RGB (value/255).

Uniform-grid blanking and ghost-array support is now implemented in the Metal
volume ray-cast backend (cell/point ghost arrays are uploaded into a
cell-centered RG8 3D texture and skipped during the march, mirroring the
OpenGL backend's in_blanking texture + g_skip logic). This fixes
TestGPURayCastVolumeUniformGridBlanking (0.0706 -> 0.0001) and
TestGPURayCastVolumeGhostArrays (0.1646 -> pass). The blanking texture is now
built from the original dataset's ghost arrays (the cell-data effective-input
proxy carries only scalars), fixing TestGPURayCastVolumeGhostArraysCellData
(0.1630 -> pass).

Hardware selection (vtkHardwareSelector) is now implemented for the Metal
volume ray-cast backend: when a selection render is active with CELLS field
association, the volume is ray-cast with a dedicated selection pipeline
(VolumePipelineType::SelectionDirect / SelectionFullscreen) that additionally
writes the picking ids {voxelId, propId, compositeIndex} into the RGBA32Uint
color attachment 1 wherever the ray accumulated opacity > 3/255 — the Metal
equivalent of the OpenGL backend's CheckPickingState + PickingActorPassExit.
The renderer attaches the shared IdsTexture (load action) to the volume pass so
depth-tested volume fragments only override the ids where their rays accumulate
opacity. This fixes TestGPURayCastVolumePicking (0.1234 -> pass): previously the
volume was invisible to hardware picking and the picker reported the cone behind
it (selection box hugged the cone), whereas the baseline picks the volume
(selection spans the whole scene).
